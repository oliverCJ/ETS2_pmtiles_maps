编辑模式的技术方案选择

EditMode 视图中，用什么技术实现可拖拽的控制点？

A

SVG 原生拖拽

复用现有 Preview.tsx 的 SVG 渲染方式，在控制点上添加 onMouseDown / onMouseMove / onMouseUp 事件，手动处理坐标转换。

核心代码思路：

// SVG viewBox 坐标 ↔ 屏幕坐标转换
const pt = svgRef.current.createSVGPoint();
pt.x = e.clientX; pt.y = e.clientY;
const svgCoords = pt.matrixTransform(
  svgRef.current.getScreenCTM().inverse()
);

优点

  • 零新依赖，项目已有 SVG 渲染基础
  • 与现有 Preview.tsx 代码风格完全一致
  • SVG 坐标系和 prefab 局部坐标系天然对应，无需额外映射
  • 轻量，不引入任何第三方库

缺点

  • 需要手动处理 viewBox 坐标转换（约 20 行代码）
  • 多点同时拖拽需要自己管理状态
B

React 拖拽库（@use-gesture/react）

引入 @use-gesture/react，用 useDrag hook 处理拖拽手势，自动处理鼠标/触摸事件的坐标计算。

核心代码思路：

const bind = useDrag(({ offset: [x, y] }) => {
  setPoints(pts => pts.map((p, i) =>
    i === activeIndex ? [p[0]+x, p[1]+y] : p
  ));
});
// SVG 元素上直接 {...bind()}

优点

  • 手势处理更健壮（支持触摸、惯性等）
  • 代码更简洁，不需要手动管理 mousedown/move/up 状态
  • 库很轻量（~7KB gzip）

缺点

  • 引入新依赖
  • 在 SVG viewBox 坐标系中仍需要做坐标映射（offset 是屏幕像素，不是 SVG 单位）
C

替换为 Canvas + React

EditMode 用 Canvas 渲染，通过 canvas.getBoundingClientRect() 做坐标映射，鼠标事件直接操作 canvas 上的点。

核心代码思路：

const rect = canvas.getBoundingClientRect();
const x = (e.clientX - rect.left) / scale + offsetX;
const y = (e.clientY - rect.top) / scale + offsetY;
// 找最近的控制点，拖拽更新

优点

  • 性能最好，适合点数多的复杂 prefab
  • 可以实现更丰富的视觉效果（高亮、hover 效果）

缺点

  • 需要重写整个渲染逻辑（道路线、控制点、节点标记等）
  • 与现有 SVG 代码完全割裂，维护两套渲染
  • 工作量最大

💡 我的推荐：选项 A（SVG 原生拖拽）

理由：

  • 项目已有完整的 SVG 渲染基础（Preview.tsx），EditMode 可以直接复用这套坐标系
  • prefab 的控制点数量经过抽稀后不会太多（通常 5-20 个），SVG 性能完全够用
  • 坐标转换虽然需要手写，但 getScreenCTM() 是标准 SVG API，代码量很少
  • 零依赖，不增加项目复杂度

B 方案的 @use-gesture/react 也不错，但在 SVG viewBox 坐标系里仍然需要做坐标映射，优势不明显。C 方案工作量太大，不值得。
