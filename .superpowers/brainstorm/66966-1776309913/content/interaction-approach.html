拖拽修复功能：选择交互方式

当你发现某个 prefab 的道路端点位置有误，你希望如何进行修复？

A

拖拽端点 → 导出修复规则文件

在 SVG 预览中直接拖拽橙色道路的端点到正确位置，修复后导出一个 JSON 文件（如 prefab-fixes.json），generator 在运行时读取这个文件，对指定 prefab 的端点坐标做覆盖替换。

优点

  • 直观，见即所得
  • 修复结果持久保存，可 commit 到代码库
  • 不改动算法代码

缺点

  • 只修复特定 prefab 的特定实例，不能修复所有同类 prefab
B

拖拽端点 → 自动生成算法补丁代码

在 SVG 预览中拖拽端点，app 分析原始坐标和目标坐标的差值，推断出应该修改 toNavCurveRoadStrings 算法中的哪个参数（如 DIVIDED_THRESHOLD 阈值），并生成建议的代码变更。

优点

  • 修复能覆盖所有同类 prefab
  • 直接改进算法质量

缺点

  • 推断算法参数较难实现，不一定准确
  • 复杂 prefab 的问题不一定能用参数调整解决
C

拖拽端点 → 显示坐标差值 → 手动写回算法

在 SVG 预览中拖拽端点到正确位置，右侧面板显示：原始坐标、目标坐标、差值（delta）。你看到这些数值后，手动分析应该调整哪段算法代码，然后去 prefabs.ts 里修改。

优点

  • 实现简单
  • 你完全掌控改哪里、怎么改
  • 可以用这些数据来改进算法

缺点

  • 需要开发者手动分析数据，有一定门槛
